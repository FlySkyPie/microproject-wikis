這個文件建立的主要目的是透過收錄常見的[設計模式](#設計模式)，並解釋各自的職責，當軟體開發者想要新增某個功能的時候，可以快速對該功能進行抽象，找到適合實做功能的模式，並定位職責邊界。

例如：「我想要新增一個功能涉及『匯入一個 PDF 到 RAG 系統中』，它應該被歸類為 Repository 還是 Service？或是其他職責拆分方式？」

LLM 便可透過 RAG 檢索本文件回應出一個符合普遍設計模式的架構方式。分類問題是 LLM 的強項，並且可以大幅降低開發者的[決策疲勞](#決策疲勞)。


LLM 應當透過這種方式降低[認知負荷](#認知負荷)，而不是生成大量的垃圾代碼提高[認知負荷](#認知負荷)，關於這方面的哲學建構請見條目：[軟體工程中的人因工程](#軟體工程中的人因工程)。
